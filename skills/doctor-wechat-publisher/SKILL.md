# 医生科普发布工具包

将一个医学选题做成可追溯、可交接的公众号审核包。默认简体中文，核心读者为普通成年人；儿童、孕期、术后和用药人群必须明确适用范围。遵守用户已有品牌要求，不套用作者个人账号或角色。

## 启动

读取用户提供的品牌与选题；配置字段见 [品牌配置](assets/brand.example.json)。缺少非关键资料时，用中性、不署医生姓名的演示配置继续；只有适用人群、医学范围不明确并影响结论时才询问。默认不需要患者资料，不索取病历。用户提供真实病例时先去标识化；未经授权不得把病例上传外部服务或放进公开样例。

确定本篇的一项读者决策，例如“如何处理及何时求助”。避免一个选题同时承担科普、诊断和产品推广。

## 证据到文章

1. 根据选题查阅当前可访问的指南、官方患者教育资料或原始研究；必须打开正文，不能用搜索摘要冒充核验。缺少浏览能力时，可用用户提供的完整资料，注明时间与局限；两者都没有时只交结构与证据缺口，不填造医疗结论。
2. 按 [证据与审核规则](references/evidence-review.md) 建立主张—来源对应关系。特别核实操作部位、方向、持续时间、适用人群、就医条件及用药边界。来源存在差异时记录差异与取舍，不把不同指南拼成未经支持的新流程。
3. 先写读者能执行的内容，再用少量解释连接原因。标题承诺必须被正文支持；不捏造门诊见闻、专家身份、疗效数据或“已经审核”。情境可以虚构，但要明确为示例。
4. 按 [交付结构](references/output-contract.md) 写入 article.json。每个医学段落列出 source_ids；编辑导语可留空。引用贴近主张，并保留机构、标题、URL和查阅时间。不得整段翻译或复制来源代替独立写作。
5. 配图默认交付可制作的任务单。图片能力可用且用户要求时再生成：普通信息图先做；操作示范要明确手位、方向、禁画项，并逐张检查。没有授权人物母版就不模仿他人IP。没有实际图片，不把提示词称作配图成品。

## 导出

在用户选定的输出目录保存 article.json、visual-brief.md、review.md；使用本技能 scripts/render_package.py 生成 article.md 和 wechat.html：

```bash
python3 <skill目录>/scripts/render_package.py <article.json路径> --out <交付目录>
```

脚本只用 Python 3 标准库；只处理本地JSON，不联网、不调用模型、不发布。它检查字段和引用ID，无法判断医学正确性。保留原始输入，避免覆盖用户已锁定的成品；有修改时另存版本。

HTML是文字排版稿，脚本不自动插图。通过浏览器检查窄屏、长标题和来源链接；粘贴微信后的样式和外链可用性仍需在微信编辑器预览。浏览器不可用时明确写“仅结构检查”，不冒充真机验证。

## 交付状态

初稿使用 draft；来源已核对但未经医生审核使用 needs_clinician_review。只有医生明确确认具体版本后，才登记 clinician_reviewed；保留审核者、日期和版本，不把该状态解释为已发布。用户明确要求公开发布时遵守其授权范围；技能本身不授权发送、收款或发布。

交付时用一段话说明：已有产物、证据缺口、尚待确认的医学/视觉事项。源文不可访问、依据不支持正文、操作图错误时先修复或删除相应内容，不阻塞其他可完成部分。

重复生成到已有目录时默认拒绝覆盖；确认要重新排版后使用 `--overwrite`，或另选版本目录。
